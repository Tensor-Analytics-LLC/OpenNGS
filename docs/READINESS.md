# OpenNGS implementation and scientific readiness

20 October 2026. Public service: https://d2j3o1re9v00qo.cloudfront.net/. Source: https://github.com/Tensor-Analytics-LLC/OpenNGS. Existing accounts, workflows, Vault material, audit records and datasets were retained. Independent Spatial and Grepeye resources were not changed.

## What is implemented and deployed

- Explore authorization uses a server-side allowlist of curated source IDs, immutable sample hashes, tools, parameters, resource ceilings, queue/concurrency limits and daily/monthly usage. Arbitrary URLs, local paths, private asset uploads and custom execution cannot bypass it.
- Research Pro requires an explicit funded grant. Per-tenant storage/upload/CPU/RAM/scratch/GPU/runtime/concurrency/queue/export limits are persisted with an audited grant version. Unsupported GPU or other runtime profiles remain blocked despite a larger numeric allowance.
- Admission reserves worst-case monetary, CPU and output/storage exposure transactionally. Integer micro-dollar accounting, daily/monthly holds, retained-capacity reservations, actual/forecast alerts and non-destructive admission holds are active.
- Resumable S3 multipart ingestion, length-bound signed parts, full-content SHA-256 verification in AWS, paired-read/index/dictionary bindings, tenant-scoped immutable run input snapshots and output commit manifests are implemented.
- The API and scientific execution are separate. Private Fargate sample execution has no task role or internet route. Funded tenant queues use reviewed digest-pinned runtimes and tenant-scoped IAM. Fresh exclusive VMs provide larger scratch, with no public IP/default internet route, encrypted volumes, bounded runtime and termination/recovery tokens.
- PostgreSQL preserves durable jobs, leases, submission intents, stages and upstream results. Ambiguous provider outcomes retain reservations for reconciliation. Completed stage outputs are validated before reuse; cache keys include scientific parameters and companion identities.
- An independent one-minute AWS schedule terminates expired exclusive workers even if the API/controller is unavailable. Its project/VPC/tenant/run checks and scoped termination role have been tested with an actual disposable worker. It has no data or secret access.
- The existing Spatial-derived canvas, inspectors, compatible connectors, preflight, execution/log views, sample results and research reporting remain integrated. User and admin entitlement/budget controls are available.
- All 138 declared public catalogue entries are discoverable across 22 categories, including academic, commercial BYOL and paid API BYOK entries without credentials. Each entry discloses runtime readiness, licence/credential requirements, tier access and validation limits. Visibility never grants execution authority. Left, right and bottom panels independently minimize and restore with saved sizes. Database/reference nodes bind authorized assets through the inspector; compatible-port suggestions are searchable without the previous eight-result truncation.
- The trusted API has bounded admission and a database pool. SSE streams have separate bounded slots, so execution monitoring does not consume ordinary request capacity.
- HTTPS uses CloudFront/WAF with a private origin. Storage is private/versioned/SSE-KMS, PostgreSQL uses certificate verification, and credentials retain authenticated envelope encryption. This is not a zero-knowledge vault: authorized application execution can decrypt a bound credential.
- OpenNGS-only DNS allowlisting and S3 endpoint restrictions are deployed. Scientific compute cannot use arbitrary internet destinations. The audit chain is checkpointed separately into a retained encrypted Object Lock bucket in 30-day Governance mode; application/worker roles have no delete or governance-bypass permission. A scoped CloudTrail trail delivers OpenNGS S3 object-access events into that archive with log validation enabled. AWS administrators remain privileged.

The [runtime capability matrix](runtime-capabilities.json) enumerates all 138 current catalogue entries with exact tested environment versions and image digests; the [application capability matrix](capability-matrix.json) records the earlier deployment snapshot. Together they document the catalogue with implementation, licence, contracts, resources, runtime publication and evidence scope. The [dependency report](dependency-readiness.json) separates Ready components from unavailable complete bundles. Catalogue presence and a successful container build are never equivalent to scientific support.

## Tier policy

| Control | Explore | Research Pro |
|---|---|---|
| Input | Immutable curated platform samples | Verified private datasets and authorized dependencies |
| Upload | Disabled by API | Explicit maximum per dataset; resumable multipart |
| Node ceiling | 2 vCPU, 4 GiB RAM, 20 GiB declared scratch, 120 seconds | Administrator-assigned finite limits, within published worker profiles |
| CPU allowance | 1 vCPU-hour/day, 8/month | Explicit daily/monthly grant |
| Concurrency / queue | 1 active, 20 queued per user; bounded global queue | Finite assigned concurrency/queue; dispatcher currently two remote stages globally |
| Stored outputs | 256 MiB per user; 64 MiB accepted output ceiling per run | Assigned stored-byte/output reservation |
| Exports | 1 GiB/month | Assigned export allowance |
| Money | Shared $200 all-in baseline, conservative per-job ceiling | Additional funded monthly allowance; no unlimited scaling |
| Retention | Derived outputs expire under the assigned 7-day policy plus a 24-hour grace period | Derived outputs expire under the longer of the accepted-job and current assigned policy, plus 24 hours; uploaded source datasets are preserved |

Storage admission prevents growth when retained capacity is full. Automatic cleanup of expired, completed-run S3 outputs is deployed and enabled. It requires a durable exact-version inventory, tenant/run-prefix validation and proof that execution has stopped. Active or interrupted jobs, reserved usage, saved-workflow references, pins, recent cache use and active reads protect outputs from deletion. Deleted artifact metadata remains in audited tombstones; stored-byte capacity is released only after deletion completes. Source datasets, migrated references, accounts, saved workflows, Vault entries and audit objects are excluded.

The live qualification deleted two versions of a disposable run object and verified pin/read-lease protection, preservation of a separate source object and run/audit history, tombstone creation and refusal of expired reads. Only that canary used a synthetic age; production retains its 24-hour grace. Cancelled multipart transfers can be reconciled and aborted; active incomplete uploads and source-data retention are not automatically purged. Unfunded or incompatible jobs receive a clear refusal/defer reason without silently reducing scientific inputs.

## Remaining work and resolution requirements

1. **Full assay qualification:** Bind exact references/indices/known sites/annotations, WES capture release and mtDNA nuclear-candidate/shift resources; run representative full-input datasets with separately funded allowances. Record accuracy, stratifications, runtime, allocation, peak memory, scratch, cost and failure recovery. Small smoke tests cannot close this.
2. **Catalogue completion:** **43 native command contracts** now have actual small-control execution evidence: 18 inherited core contracts, 17 extension tools, three additional GATK/Picard contracts and five separate-environment methods (Scanpy, SnpEff, hap.py/RTG, Strelka2 and Manta). **13 portable operations** also passed exact-image count/index/coordinate/FASTQ round-trip regressions. This does not complete every declared method: DeepVariant still needs an approved model/runtime integration and execution proof; VEP still needs the compatible executable/cache/FASTA directory-bundle implementation and qualification. Vendor/model-specific nodes retain their precise entitlement or contract blockers. Source nodes for dbNSFP, AlphaMissense, SpliceAI, CADD, REVEL, Exomiser, HPO, Ensembl, MANE, ClinGen and VEP bind actual inventory assets by exact identity; they do not provision data or imply model inference. Commercial permissions and representative scientific validation remain separate requirements.
3. **Personal-data result workbench:** Isolated, metered private-results preparation is implemented for VCF/BCF indexing, header inspection, bounded alignment pileups and supported omics tables/embeddings. The API ingests strictly checked JSON/allele records and creates its own SQLite index; it never opens a worker-supplied SQLite database or parses private BAM/HDF5 with native libraries. The current index ceiling is 512 MiB, with 4 GiB shared cache accounting and a 64 MiB complete interchange ceiling; oversized preparation fails explicitly without publishing truncated variants. Private pileup preparation currently stages complete admitted source files and then renders at most 2,000 bases/300 reads. Queue/cold-start delays apply; this is not instant byte-range-only private WGS browsing. Four isolated AWS preparations passed: exact VCF filtering/export, header inspection, CSV values and a 100-read alignment preview; cross-tenant access was denied. Result ingestion recovery reused a completed worker. Derived indexes/JSON expire only after their owning run is retention-deleted, with read/ingestion protection and explicit regeneration when the retained source permits it. See the validation report for size and timing limits.
4. **Durable operations:** Automated per-shard distributed retries, draining tier revocation, ambiguous failed-upload creation reconciliation and source-dataset retention/deletion require additional work. Expired run-prefix output reclamation is active with the protections described above. Existing source data is preserved; finite byte reservations remain in force.
5. **Large-data validation:** Only a 32-MiB interrupted/resumed upload and small native stages were exercised. Multi-hundred-GiB ingestion, high-memory VM execution and full scratch-pressure recovery remain untested. The ingestion API's configured size envelope is not proof at that size.
6. **Security/availability:** Governance checkpoints and the delivered scoped S3 data-event trail do not constitute a complete independent compliance archive. Archival of management/KMS activity, enterprise SSO/passkeys, independent penetration review and high availability remain unfinished. The low-cost single API host/single-AZ RDS can have deployment/recovery downtime.
7. **Scale:** 100 interactive synthetic users passed a bounded read test. Mixed 100-user/SSE stress, sustained workload tests and 1,000-user qualification remain pending. Upgrade the API to multiple stateless processes/hosts behind the existing edge, use a shared session/admission strategy and a larger PostgreSQL pool/database only after a measured bottleneck and funded shared capacity. Do not conflate interactive users with simultaneous genomes.

The active service is an evolving research implementation with working cloud execution and measured limits, not the completed universal scientific/clinical platform described in the broader objective.

## Catalogue usability and permissions

The live catalogue exposes 138 entries without hiding licensed or unavailable methods. Readiness, dependency, licence, Vault and compute-allowance blockers are separate facts. The admin is the sole active account and has an explicitly funded $500/month Research Pro allowance; assigning Pro is not a payment transaction. Shared platform/Explore and individual Pro ledgers remain independent. Empty generated test accounts were removed, and two synthetic principals with scientific history had access retired while their data/audit records were retained.

Library facets cover category, readiness, blocker, licence, execution access, cloud data family, assembly, format and exact known release. Server-side pagination reaches the full tenant inventory. VEP per-contig transcript/regulatory cache fragments and index/configuration files are components, excluded from primary database choices until a complete bundle is verified. Commercial/API nodes offer a direct Vault action that preselects the provider and named tool binding. Permission review records the administrator’s specific intended-use authorization and terms reference, with revocation and audit events. This does not supply a vendor licence or qualify an unimplemented runtime. No credentials or third-party agreements were fabricated.

Graph arrangement uses variable-height layered layout with barycentric ordering and nonoverlapping component placement. Orthogonal worker-computed routes avoid node rectangles; no claim is made that every nonplanar graph can have zero edge crossings. A 500-node/1,900-edge fixture passes deterministic layout, no-overlap and path-clearance checks. Independent left/right/bottom minimisation and restoration were verified in the live browser.

Validation for this source update: 221 backend tests and 29 frontend tests passed. The latest per-entry cloud state and remaining blockers are recorded in `docs/cloud-availability.json`; it is a dated snapshot, not a promise that migration or full-scale scientific validation is complete.
